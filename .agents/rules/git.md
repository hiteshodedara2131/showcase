# Git Workflow Rules

## Before any non-trivial work

```bash
git status
git log --oneline -10
git diff --stat
```

If working tree is dirty with unrelated changes, stop and ask the user what to do. Do not mix unrelated edits in a single commit.

## Branching

- `feat/<short-kebab>` — new feature
- `fix/<short-kebab>` — bug fix
- `chore/<short-kebab>` — tooling, deps, config
- `refactor/<short-kebab>` — internal restructure, no behavior change
- `perf/<short-kebab>` — performance work
- `docs/<short-kebab>` — documentation only

Keep branches short-lived. Rebase onto `master` (or `main`) before opening a PR.

## Commit messages — conventional style

```
<type>(<scope>?): <imperative summary>

<optional body — wrap at 72 cols, explain why not what>

Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>
```

Types: `feat`, `fix`, `perf`, `refactor`, `chore`, `docs`, `test`, `style`, `build`, `ci`.

Scope examples: `editor`, `home`, `canvas`, `loader`, `a11y`, `seo`, `tokens`, `deps`.

Subject line ≤ 72 chars, no trailing period, imperative mood ("add", not "added").

## What to commit / not commit

**Commit:** source, tests, configs, docs, generated files meant to live in the tree.

**Do not commit:** `.env*`, secrets, generated artifacts (`.next/`, `node_modules/`, `*.tsbuildinfo`), large binary sources that should be in a CDN, scratch experiments. The `.gitignore` already covers the standard set — do not weaken it.

## Inspecting before commit

```bash
git status
git diff --stat
git diff
```

Check for:

- Stray `console.log`
- Commented-out code
- Debug `useEffect` triggers
- Unrelated refactors sneaking in
- Generated AGENTS.md block changes (auto-managed by `next dev`; committing it is fine, but the diff is large — review it once)

## Special files in this repo

- **`AGENTS.md`** is auto-regenerated by `next dev` (`node_modules/next/dist/server/lib/generate-agent-files.js`). Treat it as a managed file. If `next dev` rewrites it, the diff is expected — commit it as part of your work to keep the tree clean.
- **`ARCHITECTURE.md`** is the architectural source of truth. Architectural changes go there first, in a separate `docs:` commit.
- **`.agents/`** holds agent rules and skills. Changes here are tooling, not product code.

## Push & PR

- Do not push unless the user explicitly asks.
- When a PR is opened, the GitHub Actions lint + typecheck + build workflow must pass.
- Use the PR template at `.github/pull_request_template.md`.
